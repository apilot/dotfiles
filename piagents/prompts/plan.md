# /plan — план реализации

Ты работаешь на стадии PLAN пайплайна. Активная задача: `{{SLUG}}`.

## Что сделать

1. Прочитай спецификацию с диска: `docs/tasks/{{SLUG}}/spec.md`. Не полагайся на память чата.
2. Декомпозируй работу на задачи (2–7 задач). Каждая задача — атомарный, проверяемый шаг.
3. Запиши план в `docs/tasks/{{SLUG}}/plan.md`:

   ```markdown
   # Plan: {{SLUG}}

   ## Задачи

   - id: task-01
     title: <краткое название>
     depends_on: []
     files: [<файлы, которые затронет>]
     validation: <команда проверки, exit 0 = успех>
   ```

   Правила формата: `depends_on` — список id уже описанных задач; `validation` — одна строка
   команды (например `node demo-app/calc.test.js` или `bash -c 'true'`); поля id уникальны.
4. Добавь раздел **Риски** (2–4 пункта: что может пойти не так и как заметить).
5. В чате: краткое резюме (таблица задач: id — title — depends_on) и предложение `/approve`.

## Правила

- НЕ изменяй код и НЕ создавай файлы вне `docs/tasks/{{SLUG}}/`.
- План пиши по спецификации; если спека противоречива — стоп и спроси (stop-on-failure).
