# Делегирование — глобальное правило

> Правило владельца (2026-09-17): «Всё, что можно делегировать с минимальным промтом — делегируем.
> Если задача большая — дробим на маленькие куски и делегируем. Сами следим за выполнением.»

## Правила

1. **Делегируем всё, что можно делегировать.** Кодинг — CoderAgent, тесты — TestEngineer/Tester,
   ревью — Reviewer/DeepSeek Reviewer, поиск/анализ — explore/ContextScout, документация —
   Documentation/DocWriter. Оркестратор НЕ пишет код/спеки сам, пока пакет не стал тривиальным
   (правка 1–2 строк по ходу верификации — можно).

2. **Минимальный промт.** Делегируем по ссылке на артефакт, а не пересказом: путь до плана/подзадачи
   (план, `subtask_NN.json`, `context.md` сессии) + 1–2 предложения рамки. Дублирование требований
   в промте — запрещено: источник истины один, артефакт.

3. **Большое → маленькое.** Задача >4 файлов / >1 пакета — сначала дробим (TaskManager или вручную по
   пакетам), затем делегируем куски. Один субагент = один атомарный кусок с проверяемым результатом.
   Независимые куски запускаем параллельно.

4. **Сами следим за выполнением.** Оркестратор обязан:
   - ждать завершения каждого субагента и проверять его результат (diff, статусы, файлы);
   - зависший/прерванный субагент — перезапустить (максимально короткий цикл контроля);
   - самому прогонять гейты, недоступные субагентам (тесты/линтеры/сканеры, живой стенд, git);
   - верифицировать RED→GREEN для TDD-кусков (stash-методом или повтором на родителе);
   - держать чистоту тестовых данных и коммитов.

## Признаки нарушения

- Оркестратор пишет многострочный диф сам → стоп, оформить кусок и делегировать.
- Промт субагенту длиннее артефакта → стоп, промт лишний, сослаться на артефакт.
- Субагент «завершился», а гейты не прогнаны оркестратором → работа не закончена.
